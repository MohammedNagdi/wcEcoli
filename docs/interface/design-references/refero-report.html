REFERENCE 01 / RESULTS OVERVIEW

Seline Analytics: Overview first, details within reach

Marketing capture with embedded dashboard. Source: Refero.

Observed pattern

The embedded dashboard has a labeled left rail, filter and date controls above the data, a compact metrics strip, and two main chart panels. Tooltips in the capture attach values to specific points.

Apply to wcEcoli

Use this hierarchy for experiment outcomes: identify the experiment and condition first, then show key biological metrics and time series. Keep seed count, units, uncertainty, and the wildtype reference beside the metrics. Make filters apply consistently across the view.

Evidence limit

This is a product preview, not an inspected result-comparison flow. Its decorative headline and mascot have little value in a scientific work area.

REFERENCE 02 / RUN MONITORING AND NAVIGATION

Asana: Persistent navigation + status summaries

Standalone dashboard screen; public thumbnail. Source: Refero.

Observed pattern

A persistent labeled sidebar accompanies status cards and chart panels. The capture includes an Add chart action, filter indicators under metrics, and a bottom-left Help & getting started entry.

Apply to wcEcoli

Translate the status overview into queued, running, completed, and failed simulation counts. Keep a labeled help entry available from every phase. Put deeper job diagnostics behind the selected run so the overview stays easy to scan.

Evidence limit

The screen concerns tasks, not scientific jobs. A screenshot cannot establish that help, keyboard navigation, or filters work well. Inspect those behaviors in a later prototype.

REFERENCE 03 / GUIDE AND CONTEXTUAL HELP

Mintlify: Topic navigation + search + page outline

Marketing capture with embedded documentation UI. Source: Refero.

Observed pattern

The documentation preview shows a topic sidebar with Quickstart selected, Guides/API Reference/Changelog tabs, Search or ask, a central article, and an On this page outline.

Apply to wcEcoli

Organize the Guide around first simulation, experiment types, conditions, interpreting results, and troubleshooting. Link local help directly to the relevant section. Use short definitions and worked examples for students, with technical detail available alongside them.

Evidence limit

Borrow the documentation structure. The illustrated marketing hero is not evidence for an in-product help flow, and an AI answer should not replace the authoritative scientific explanation.

REFERENCE 04 / EXPERIMENT AND BATCH CATALOG

Reworkd: Filter toolbar + dense, aligned table

Archived marketing capture with embedded data table. Source: Refero.

Observed pattern

The preview places a search field and dropdown filters directly above a table. Rows separate an ID, status, description, due field, and attachments; a selected row is visibly marked.

Apply to wcEcoli

Use one table for experiment or batch browsing, with name, variant, condition, seed count, status, and updated time. Place search and filters above it. Keep technical identifiers secondary to readable experiment names.

Evidence limit

The capture announces a February 2025 product sunset. Treat it as an archived pattern reference. The table is visible, but its editing, pagination, and error behavior are not verified.

REFERENCE 05 / PRIMARY VISUAL FOUNDATION

Grafbase: Neutral technical workspace + labeled rail

Marketing capture with embedded console UI. Source: Refero.

Observed pattern

The capture uses a mostly white and charcoal foundation. Its embedded console has a labeled sidebar, explicit environment metadata, thin panel borders, and line charts. Refero describes Inter as the main type family.

Apply to wcEcoli

Use this neutral, precise foundation for the report and simulator direction. Preserve readable navigation labels, a clear heading hierarchy, and quiet separators. Let plots and run states carry meaning rather than adding decorative color throughout the interface.

Evidence limit

The large marketing headline, banner gradient, and conversion layout belong to the marketing surface. They do not justify the layout or color semantics of scientific charts.

REFERENCE 06 / EMPTY RESULTS AND FIRST USE

Reown: Contextual empty state with explanation

Standalone analytics screen; public thumbnail. Source: Refero.

Observed pattern

Analytics remains a clearly selected tab while chart-shaped placeholders explain that no data is available yet and suggest setup or waiting for activity.

Apply to wcEcoli

Distinguish no experiments, no completed results, an active run, and no matches for the current filter. State the reason and offer the relevant next action: create an experiment, view its progress, or clear filters.

Evidence limit

The muted placeholders offer context but are easy to mistake for loading. Use explicit text in wcEcoli, and do not imply that an empty-state action or recovery flow was verified here.

RECOMMENDATION / ADAPTATION TO THE USER BRIEF

One clear research journey

Explore

Find the gene and biological context.

Simulate

Set the experiment, review, then run.

Analyze

Read outcomes, compare, then export.

Reference lock

Grafbase owns the neutral canvas, sans-serif hierarchy, and quiet borders. Seline contributes the results hierarchy; Asana the status overview and help entry; Mintlify the Guide structure; Reworkd the catalog toolbar; Reown the empty-state distinction. Marketing gradients, large headlines, and mascots stay within their original marketing roles.

Decision ledger

DecisionEvidenceReason
Quiet technical visual foundationGrafbaseKeep attention on scientific content.
Filters and key outcomes before plotsSelineMake the selected data context explicit.
Persistent help entry and status totalsAsanaOrient newcomers and monitor work.
Searchable Guide with topic navigationMintlifySupport both learning and lookup.
Readable catalog with a filter toolbarReworkdFind experiments without opening each one.
Explicit, actionable empty-state reasonsReown + user briefExplain what to do next.
Review settings and expose uncertaintyUser brief / proposed scientific adaptationImprove understanding; requires usability evaluation.

Prototype priorities

1 / Navigation and help
Keep the three phases visible. Make Help & getting started permanent. Link parameter help to a searchable Guide.

2 / Setup and progress
Give students a short example-led start. Review settings before launch. Show the run stage and a readable failure explanation.

3 / Scientific interpretation
Keep control, units, seeds, uncertainty, and configuration differences close to the plots. Put raw outputs within reach.

Proposed setup sequence: choose an example or experiment type, configure the scientific setup, review, run, then analyze. This is a recommendation for wcEcoli, not a flow observed in Refero.
